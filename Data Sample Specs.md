# Egocentric Video Clip and Caption Dataset

Paired first-person video clips and bilingual structured annotations (Chinese + English). Each sample has one MP4 clip and one JSON caption describing what the camera-wearer did, the scene, the camera motion, and a step-by-step breakdown with object-level state changes.

## Overview

- **Samples:** 1,503
- **Total source-caption time:** 12:10:33.500 (43,833.500 seconds; 12.176 hours), computed from the `start-end` seconds encoded in the source caption filenames
- **Sample unit:** one root-level `<clip_uuid>/` directory
- **Video location:** `<clip_uuid>/<clip_uuid>.mp4`
- **Caption location:** `<clip_uuid>/<clip_uuid>.json`
- **Pairing key:** the directory name and both file stems are the same `clip_uuid`
- **Language:** every free-text field is paired — `xxx_zh` (Chinese) + `xxx_en` (English)
- **Timing:** all `start_sec`/`end_sec` values inside the caption JSON are relative to this clip start (i.e. `0.0` = the start of `<clip_uuid>.mp4`), not the original source video

## Dataset layout

The packaged bucket is organized around clip UUIDs:

```text
.
├── <clip_uuid>/
│   ├── <clip_uuid>.mp4
│   └── <clip_uuid>.json
├── scene_uuid_map.json
├── task_category_uuid_map.json
├── smaller_sample_uuid_map.json
├── scene_list.json
├── task_category_list.json
├── task_category_map.json
└── README.md
```

The MP4 and JSON inside one `<clip_uuid>/` directory are the video/caption pair for the same sample. Caption filenames are clip UUIDs in this packaged dataset; they do not encode the original source session, source segment index, or source time range.

The root metadata files provide label-oriented lookup:

- `scene_uuid_map.json` maps each merged semantic scene group to the clip UUIDs carrying that scene. The root scene vocabulary is merged into 6 groups: `Counter`, `Courier Point`, `Cybercafe`, `Kitchen`, `Laundry Room`, and `Shopping Mall`.
- `task_category_uuid_map.json` maps each observed English `task_categories_en` value to the clip UUIDs carrying that task category.
- `smaller_sample_uuid_map.json` is a deterministic smaller-sample index grouped by 6 semantic scene groups, then by task category, with up to 10 clip UUIDs per scene/category cell. Each sampled UUID is also listed in `samples` with its corresponding fine-grained `tasks_zh` / `tasks_en` labels for that task category.
- `scene_list.json` is the merged 6-group scene vocabulary as a flat list with `id`, `zh`, and `en` fields.
- `task_category_list.json` is the closed 13-category task vocabulary as a flat list with `id`, `zh`, and `en` fields.
- `task_category_map.json` contains task-category metadata plus the mapping from fine-grained `tasks_*` labels to their high-level task categories.

The reverse-index and smaller-sample map files use UUID lists because `scene_label_en` and `task_categories_en` are list fields. Individual caption JSON files keep the upstream raw `scene_label_*` strings; the root `scene_list.json` and `scene_uuid_map.json` merge those raw scene labels into the 6 semantic scene groups above. One clip UUID can therefore appear under more than one map key.

## Caption JSON structure

```jsonc
{
  "global": { ... },   // segment-level annotation
  "steps":  [ ... ]    // ordered, time-stamped steps
}
```

These are the only two top-level keys.

## `global` fields — quick reference

| Field | Type | One-line description |
|---|---|---|
| `summary_zh` / `summary_en` | string | One-sentence summary of the whole segment. |
| `scene_zh` / `scene_en` | string | **Free-text** description of the environment and notable objects in view. |
| `scene_label_zh` / `scene_label_en` | list[string] | Short scene **tags** (e.g. `["kitchen"]`). |
| `camera_motion_zh` / `camera_motion_en` | string | Free-text summary of camera motion across the segment. |
| `tasks_zh` / `tasks_en` | list[string] | **Fine-grained** task labels — what the user is trying to accomplish. Open vocabulary. |
| `task_categories_zh` / `task_categories_en` | list[string] | **High-level** task category — closed vocabulary of 13 (see §"Task categories"). |
| `rubrics` / `rubrics_en` | list[string] | Upstream-provided list of key objects and actions. **Source-video-level**, see clarification below. |

## `global` fields — clarifications for easily-confused pairs

The five pairs below look similar by name but differ in shape, source, and intended use. Read this section before training.

### `scene_*` vs `scene_label_*`

| | `scene_zh / scene_en` | `scene_label_zh / scene_label_en` |
|---|---|---|
| Type | `string` (free-form sentence) | `list[string]` (short tags) |
| Granularity | A descriptive paragraph: layout, lighting, salient objects | A scene category, usually 1 tag |
| Vocabulary | Open | Small upstream tag set in each caption; root metadata files merge these tags into 6 semantic scene groups. |
| Source | Generated by the video-understanding model | From the upstream human metadata's `scenes` field |
| Use it for | Captioning / VQA / retrieval-style training | Coarse filtering, balancing, or as a categorical label |
| Caveat | — | 2 samples have `[]` — upstream had no scene tag and we preserved that faithfully. |

### `tasks_*` vs `task_categories_*`

| | `tasks_zh / tasks_en` | `task_categories_zh / task_categories_en` |
|---|---|---|
| Type | `list[string]`, length 1–2 | `list[string]`, **same length** as `tasks_*`, parallel by index |
| Vocabulary | **Open** — 560 distinct labels in this dataset | **Closed** — exactly 13 values (see table below) |
| Granularity | Specific task with object reference (e.g. `煮泡面 / cooking instant noodles`, `安装键盘键帽 / installing keyboard keycaps`) | High-level category (e.g. `Light Meal Cooking & Food Prep`, `Computer Peripheral Maintenance`) |
| Generation | Per-sample LLM call grounded in `summary` + all step descriptions + `rubrics` | Deterministic rule-based mapping from each `tasks_*` entry |
| Multi-task samples | 30 / 1,503 segments have 2 entries (segment contains two clearly-decoupled goals) | Same — index `i` of `task_categories_*` is the category of `tasks_*[i]` |
| Use it for | Fine-grained instruction-style supervision | Classification, evaluation breakdowns, balancing |

The two arrays are **always aligned by index**. Example: `tasks_en = ["cooking instant noodles"]` / `tasks_zh = ["煮泡面"]` maps to `task_categories_en = ["Light Meal Cooking & Food Prep"]` / `task_categories_zh = ["简餐与食材处理"]`. Multi-task example: `tasks_en = ["unpacking a parcel", "packing a parcel"]` / `tasks_zh = ["拆快递", "打包快递"]` maps to `task_categories_en = ["Express Parcel Handling", "Express Parcel Handling"]` / `task_categories_zh = ["快递包裹处理", "快递包裹处理"]` (duplicates allowed).

### `tasks_*` vs `rubrics`

| | `tasks_*` | `rubrics / rubrics_en` |
|---|---|---|
| What | What the user is **doing in this segment** | Key **objects** + a few action keywords from upstream human annotation |
| Scope | This segment only | The **whole source video**, not segment-specific |
| Shape | Verb-phrase (`分拣快递 / sorting parcels`) | Mostly noun phrases plus a few action words (`["灰色垃圾桶", "纸杯", "倒水"]`) |
| Faithful to this segment? | Yes | **Not always** — items in `rubrics` may not actually appear in this particular segment, since they describe the parent video |
| Use it for | Task supervision | Conditioning / hints, **not** ground truth for what's visible in this clip |

### `summary_*` vs `scene_*` vs `camera_motion_*`

All three are free-text strings, but they cover orthogonal aspects of the segment:

- `summary_*` — **what happens** (actions, sequence, outcome). One sentence covering the whole clip.
- `scene_*` — **where it happens and what's around** (environment, layout, salient props). No actions.
- `camera_motion_*` — **how the camera moves** (pan, tilt, static, follow-hand, etc.). No environment description, no actions.

Treating them as interchangeable will hurt model behavior. Use them as distinct supervision channels.

## Task categories (closed vocabulary, n=13)

`task_categories_zh / task_categories_en` is restricted to these 13 values. Categories are designed to be mutually decoupled.

| `_zh` value | `_en` value | Covers |
|---|---|---|
| 快递包裹处理 | Express Parcel Handling | Sorting / packing / unpacking / labeling / scanning / flipping / conveyor placement |
| 小商品分拣与打包 | Small Goods Sorting & Packing | Disposable toothbrushes / toiletries / soap / snacks / generic non-courier goods |
| 餐厨用具清洗 | Dishware & Kitchenware Washing | Cups, bowls, pots, kettles, strainers, baking trays, ashtrays, food containers |
| 布巾清洗 | Cloth & Rag Washing | Rags, towels, scouring pads |
| 电脑外设维护 | Computer Peripheral Maintenance | Keyboards / mice / headphones / keycaps — cleaning, disassembly, assembly, repair |
| 桌面与台面整理 | Desk & Counter Tidying | Wiping desks / countertops, organizing desks, cable management, internet-cafe counters |
| 地面清洁与垃圾处理 | Floor Cleaning & Trash Handling | Sweeping, mopping, taking out trash, sink cleaning, cafe floor cleaning |
| 个人卫生 | Personal Hygiene | Hand-washing, hand-drying, hand cream |
| 饮品制作与递送 | Drink Preparation & Serving | Milk tea / juice / lemonade prep, mixing, capping/labeling cups, serving, ashtray service prep |
| 简餐与食材处理 | Light Meal Cooking & Food Prep | Boiling instant noodles, cutting ingredients, opening food packaging, cooking |
| 数字设备使用 | Digital Device Operation | Using computer / phone / calculator, typing, taking photos, scrolling, QR-code login |
| 账目核算与收银 | Bookkeeping & Cashiering | Accounting, cashiering, ID registration, data entry, reconciliation |
| 物品摆放与陈列 | Item Placement & Display | Placing name plates, price tags, retrieving from counter, miscellaneous item handling |

The bucket-root `task_category_uuid_map.json` is a reverse index from each English task category label above to the clip UUIDs that use it.

## `steps[]` — quick reference

Ordered array of action units that together cover the segment. Each step:

| Field | Type | One-line description |
|---|---|---|
| `step_id` | string | Stable id (e.g. `"s01"`) |
| `start_sec` / `end_sec` | float | Time range, **relative to segment start** |
| `name_zh` / `name_en` | string | Short name of the action |
| `description_zh` / `description_en` | string | Detailed description of what happened |
| `confidence` | float | Annotator-model confidence in the step |
| `primary_objects[]` | list[obj] | Objects involved in this step (see below) |
| `actions[]` | list[obj] | Sub-action slices within this step (see below) |
| `boundary_evidence` | object | Visual anchors marking step start/end (`start_anchor` / `end_anchor` + `_en`) |

### `primary_objects[]` items

| Field | Type | One-liner |
|---|---|---|
| `object_id` | int | Step-local id; referenced by `actions[].object_id` |
| `label_zh` / `label_en` | string | Object name |
| `attrs` / `attrs_en` | list[string] | Attribute strings: `"颜色:白"` / `"Color: White"` etc. |
| `state_change` | string | Object's state transition during this step (`"empty -> contains water"`) |
| `state_change_en` | string | English version, **only present when `state_change` was originally Chinese** |

### `actions[]` items

| Field | Type | One-liner |
|---|---|---|
| `start_sec` / `end_sec` | float | Sub-action time range, relative to segment start |
| `verb_zh` / `verb_en` | string | Action verb |
| `object_id` | int | References `primary_objects[].object_id` in the same step |
| `hand_side` | string | `"left"` / `"right"` / `"both"` |
| `hand_pose` / `hand_pose_en` | string | Hand pose (`"pinch"`, `"grip"`, …) |
| `camera_motion` / `camera_motion_en` | string | Camera motion during this sub-action |

## Known edge cases

- 2 samples have empty `scene_label_*` arrays (`[]`) because the upstream metadata had no scene tag for them. Faithfully preserved.
- `actions[].camera_motion_en` is missing for ~⅔ of action items (the Chinese `camera_motion` is always present; English back-translation was only run on a subset).
- `primary_objects[].state_change_en` is only present when the original `state_change` was Chinese; if it was already English, no `_en` sibling is added.
- `tasks_*` is never empty and never longer than 2.
